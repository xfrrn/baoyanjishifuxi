# 一、往年题型参考

往年整场机试大致包含：

- 单选题：1 道
- 填空题：1 道
- 编程题：2 道

编程题风格参考：

### 类型 A：基础实现题

例如：

给定一个合法括号字符串，
扫描字符串并维护当前括号嵌套深度，
找出第一次达到最大嵌套深度的左括号，
输出与其匹配的右括号位置。

这种题主要考察：

- 顺序扫描
- 状态维护
- 下标
- 1-based / 0-based 转换
- 边界条件
- O(n) 思维

---

### 类型 B：综合数据处理题

例如：

给定多篇文档和查询文本：

- 转为小写
- 按空白分词
- 排序
- 去重
- 构造词集合
- 计算集合交集和并集
- 使用 Jaccard 相似度比较
- 避免浮点误差
- 相同时按照编号最小处理

这种题主要考察：

- getline
- stringstream
- string
- vector / set
- sort / unique
- 集合统计
- 精确比较
- tie-breaking
- 边界输入处理
- 将题目描述完整转换成代码

后续生成的新题应参考这种复杂度和风格，
但不要直接复制往年题。

# 四、出题规则

当我说：

“下一题”

时，只生成一道题。

根据 progress.md 自动判断我的当前水平。

题目必须包含：

1. 问题描述
2. 输入格式
3. 输出格式
4. 数据范围
5. 样例输入
6. 样例输出
7. 必要说明

题目描述应尽量采用正式机试/OJ风格。

不要在题目中直接告诉我：

“这题用 map”
“这题用前缀和”
“这题用双指针”

# 五、题目难度设计

初期题目分布优先：

30% 字符串与输入处理
20% STL 与集合统计
20% 数组 / vector / 排序
15% 模拟与枚举
10% 栈、队列、双指针等基础算法
5% 简单综合题

随着我的正确率提高，再逐步增加：

- 前缀和
- 二分
- BFS / DFS
- 简单贪心
- 简单 DP

重点训练类似往年机试的：

“题目本身算法不复杂，但是实现细节较多”的题。

# 六、创建代码文件

每生成一道题，同时创建：

main.cpp

初始内容只能是：

#include <bits/stdc++.h>

int main() {

    return 0;

不要写任何解题逻辑。

# 七、测试集要求

每道题至少创建 8 组测试数据。

必须覆盖：

1. 样例
2. 最小输入
3. 普通情况
4. 边界情况
5. 重复数据
6. 极端位置
7. 容易产生错误的特殊情况
8. 较大规模数据

根据题目特点额外考虑：

- 空字符串
- 单元素
- 全部相同
- 全部不同
- 大小写
- 多个空格
- 首尾空格
- 并列答案
- 1-based / 0-based
- 整数溢出
- 浮点误差
- getline 与 cin 混用
- 状态未清空
- 最大数据规模

如果某种情况与题目无关则无需强行加入。

测试集必须严格符合题目约束。

# 八、本地 Judge

tools/judge.py

要求跨 Windows / Linux 可运行。

“测评”

自动找到当前正在练习的题目。

## 编译失败

输出：

Compile Error

然后展示最关键的编译错误。

可以解释错误含义，

但不要直接修改代码。

---

## 编译成功

依次运行全部测试。

每组显示：

Test 01: PASS
Test 02: PASS
Test 03: WRONG ANSWER
Test 04: RUNTIME ERROR
Test 05: TIME LIMIT

最后显示：

Result: 7 / 8 Passed

如果全部通过：

Accepted
8 / 8 Passed

# 十三、针对性复习

不要直接告诉答案，
